Answer key + scoring rubric.

The companion to the assessment. Do not distribute to trainees. Use during scoring and to guide the debrief conversation.

Trainer only

Keep this document separate from the assessment. If a trainee sees the answers before their test, the score means nothing — the point isn't the number, it's finding real gaps to fix.

Section A

Appropriate use — Y or N.

5 pts · 1 pt each

A1. Paste our production Redis password into ChatGPT to ask why the connection is slow.

N — Not appropriate

Never paste production credentials, ever. Even "just to ask why they're slow". Sanitize first. If a trainee marks this Y, they need to redo Module 4 before touching real Tathkarah work.

A2. Ask Claude to summarize a 200-line stack trace from tk-flight-jazeera.

Y — Appropriate

Stack traces are typically safe (they contain file paths, line numbers, function names — no user data unless the panic captured a live request body). Claude reads them faster than a human.

A3. Have Claude generate a first draft of test cases for the new coupon endpoint.

Y — Appropriate

Excellent use. Test case generation is one of the highest-leverage uses of AI. Human reviews the generated tests before merging.

A4. Ask Claude the current exchange rate for KWD → USD to display in the app.

N — Not appropriate

Live data question. Claude has a training cutoff and cannot know today's FX rate. Use an FX API. If Claude gave a specific rate, it would be a hallucination.

A5. Ask Claude to compute the total commission across yesterday's 4,713 bookings from our database.

N — Not appropriate

Two problems: (1) Claude can't do reliable arithmetic on 4,713 rows, (2) even if it could, we'd be sending real transaction data to a third party. Use a SQL query.

Section B

Security judgment — safe or not.

10 pts · 2 pts each

B1. Go source of handlers/booking.go with all imports and function bodies visible.

SAFE — with a check

Usually safe — but only if the trainee first scans the file for hardcoded secrets, internal URLs, or embedded API keys. Award full 2 pts if the answer mentions this precondition. Award 1 pt for unqualified "safe".

B2. postgres://tkdev:Pr0d_Passw0rd@10.0.4.12:5432/tathkarah

NOT SAFE

Two secrets in one line: production password + internal IP. Both must be sanitized. If a trainee misses this, they must redo Module 4 immediately.

B3. Screenshot of a customer's booking confirmation with name, phone, PNR, amount.

NOT SAFE

Full PII combination + booking data. Never. If the trainee needs to discuss the layout, describe it in words or use a fake mockup.

B4. Stack trace with only file paths, function names, line numbers.

SAFE

Pure code metadata. No user data. Standard safe paste.

B5. CSV of failed transactions — masked cards but real customer emails.

NOT SAFE

Emails are PII, especially combined with transaction data (re-identification). Replace emails with test1@example.com etc. before pasting. Common mistake — masked cards feel "safe enough", but the combination isn't.

Section C

Spot the hallucination.

5 pts · 1 pt each

C1. "KEYDB.PRUNE 30d command."

FABRICATED

There is no such command. KeyDB is a Redis fork and neither has a built-in "prune by age" command. Pure fabrication — key detection point is the specific, plausible-sounding syntax.

C2. "Go 1.22 introduced range-over-int."

TRUE

Correct. Range-over-int shipped in Go 1.22. for i := range 10 is valid Go 1.22+ syntax.

C3. "In micro/go-micro/v2, config.Get(a, b, c) navigates nested keys."

TRUE

Correct. config.Get is variadic on strings. Verified live in this project on 2026-06-14 by reading the source.

C4. "Flutter Column has an alignment parameter."

FABRICATED

Half-truth. Column has mainAxisAlignment and crossAxisAlignment, not a single alignment. This is the classic "sounds right, isn't quite" hallucination.

C5. "MongoDB 6 removed db.eval()."

TRUE

Correct. db.eval() was deprecated in MongoDB 3.0 and removed in later versions. Still — a good candidate to verify, since a hallucinated version number would be plausible here.

Section D

Prompt writing — 3 pts each.

24 pts total
Universal rubric for D1–D8
  • 1 pt Context: names the repo, language, branch, or a real anchor file
  • 1 pt Specificity: the ask is one concrete thing, not a vague request
  • 1 pt Constraints or format: tells Claude either what to avoid, or what shape the answer should take

D1. Rewrite: "add caching to the search endpoint"

Model answer
In tk-hotel-main's handlers/search.go, cache the response of POST /hotels/search in KeyDB (already wired at localhost:6379). Cache key = SHA1 of the request body. TTL 60 seconds. On cache miss, call the underlying handler and store the result. Log hit/miss ratio at info level. Show me the diff only.

D2. Rewrite (tk-flutter-mobile-app home hotel tile): "make the tile bigger"

Model answer
In lib/Presentation/home_view/home_screen.dart, the hotel tile currently renders at 140x140. Increase to 180x180 while keeping the current border radius (12) and shadow. The grid must still show 2 tiles per row on iPhone SE width (375px). RTL layout must still align correctly.

D3. Rewrite: "debug why it's slow"

Model answer
The /hotels/search endpoint on tk-hotel-main is taking ~3 seconds in dev. Baseline (2 weeks ago) was ~400ms. What are the most likely causes to check, ordered by probability, given this stack: Go micro/go-micro/v2, KeyDB cache, Typesense search, MongoDB store. Suggest one debug command per hypothesis.

D4. Prompt for diagnosing the tk-flight-jazeera panic.

Model answer
I'm getting this panic starting tk-flight-jazeera in our dev environment. The service is on feature/v4.5, Go 1.22. It uses github.com/Tathkarah-for-travela-and-tourism/tk-cache-client for cache init via cache.InitCache(c, provider, addr, pass, 0). Full trace: [paste]. What's the most likely cause? Show your reasoning. Then propose the specific one-line change that would surface a clearer error message next time this fails.

D5. Hotel search slowdown prompt.

Model answer
The POST /hotels/search endpoint on tk-hotel-main is taking ~3 seconds in dev. Baseline (2 weeks ago) was ~400ms. Nothing obvious changed in that repo. Stack: Go micro/go-micro/v2 · KeyDB cache at localhost:6379 · Typesense at localhost:8108 · MongoDB at localhost:27017. Rank the most likely causes by probability. For each, give me one debug command I can run right now to test the hypothesis. Format: one line per hypothesis, one line per command.

D6. Health endpoint for tk-payment-tap.

Model answer
In tk-payment-tap, add a GET /health endpoint that returns 200 with a JSON body {status:"ok", lastGatewayCallAt:"…"}. If we've never called the upstream Tap gateway, return lastGatewayCallAt:null. Match the existing handler pattern (see any handler in service/). Register it in the router the same way. Don't touch go.mod. Show me the diff only.

D7. QA prompt for Arabic hamza test cases.

Model answer
For the flight passenger form on tk-flutter-mobile-app, generate 15 test scenarios focused on Arabic name input. Include: - Names with hamza in different positions (initial ء, medial أ إ ؤ ئ, final) - Names with taa marbuta (ة) - Mixed Arabic + Latin (a common real case) - Very long names (60+ characters) - Names with diacritics (تشكيل) - RTL/LTR rendering edge cases For each scenario: input, expected UI behavior, expected data sent to backend. Format as a numbered list.

D8. Server admin prompt for slow alpha-flight VPN host.

Model answer
I have SSH access to alpha-flight (VPN host, Ubuntu, runs several tk-* services under systemd). Users report the machine is slow. Give me a ranked list of the six most useful commands to run to diagnose, in order — cheapest / most-likely-informative first. For each command, one sentence on what to look for in the output.
Section E

Applied task — 6 pts.

Take-home · debrief in person
Rubric
  • 2 pts — Completed the task. They did redo a real piece of work with Claude Code. Not a made-up hypothetical.
  • 2 pts — Named a real mistake. They identified something Claude got wrong, missed, or hallucinated. "It worked perfectly" is 0 points — either they didn't verify, or they picked too easy a task.
  • 2 pts — Honest reflection. The "would use again?" answer shows judgment — they know for what tasks it fits and where it doesn't. A blanket "yes always" or "no never" is 1 point maximum.

This is a debrief conversation, not a marked answer. Sit with the trainee for 10 minutes and go through their writeup. This is where you catch overconfidence, blind spots, and false modesty.

Score interpretation

45–50
Fluent. Ready to use AI on real Tathkarah work with light supervision. Include them in the AI clinic as a contributor, not just a listener.
40–44
Passing. Cleared the bar. Pair them with a stronger user for the first two weeks of real use to catch small mistakes before they become expensive.
30–39
Needs review. Identify which section(s) they lost points in, have them redo those modules, retake the failed sections in one week. Do not use AI on production-adjacent work yet.
Below 30
Restart the workbook. No shame — training didn't land. Try a different format (paired live sessions, walkthrough with mentor) before the second attempt.
Any B section score below 6/10
Overrides everything above. Regardless of total score, if security judgment is weak, they cannot use AI on Tathkarah work until they retake Section B and pass it. This is the one non-negotiable.
