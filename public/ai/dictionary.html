Legend: abbreviations in MONOSPACE · practical notes in italics · related terms after see also.

A

Agent

Tools & agents

An AI configuration that can autonomously take actions in the world using tools, rather than only producing text. An agent typically has a goal, a set of tools it can call, and a loop that runs until the goal is met or a stopping condition triggers.

Claude Code is an agent environment: it reads files, runs commands, edits code, all on your behalf. Contrast with a plain chat window, which only produces text.

See also Tool use, Orchestrator, Autonomous agent.

Alignment

Safety & governance

The broad problem of making an AI system behave the way the humans deploying it intend. In practice, alignment includes helpfulness, honesty, harmlessness, and following instructions. Achieved through training techniques (RLHF, constitutional AI) rather than emerging naturally.

See also RLHF, Constitutional AI, Safety.

Attention

Model & training

The core mechanism in a transformer that lets the model, when generating each output token, weight the importance of every earlier token in the context. "Attention is all you need" — the 2017 paper by Vaswani et al. — introduced this architecture and started the modern era.

Why the beginning and end of your prompt matter more: attention concentrates there. Bury important instructions in the middle and they lose weight.

See also Transformer, Context window.

Autonomous agent

Tools & agents

An agent that runs a multi-step task without waiting for human confirmation at each step. It plans, executes, evaluates, and iterates until completion or failure.

High-leverage when the task is well-scoped; high-risk when the tools it can call have side effects. For Tathkarah production work, keep a human in the loop on any autonomous change.

B

Base model

Model & training

The raw output of pretraining, before any fine-tuning or alignment. Base models are essentially very powerful autocomplete engines — they'll continue any prompt in the style of their training data, without any assistant-like behavior.

See also Pretraining, Fine-tuning, Foundation model.

Benchmark

Model & training

A standardized dataset and scoring protocol used to compare model performance. Examples: MMLU (general knowledge), HumanEval (code), GSM8K (math). Useful for comparing models at a coarse level; often misleading for predicting real-world usefulness.

Do not choose your model by leaderboard. Choose it by running your actual work through it.

C

Chain-of-thought

CoTPrompting

A prompting technique where the model is instructed to reason step-by-step before producing a final answer. Empirically improves performance on complex tasks. Modern chat models often do this automatically, but asking explicitly ("think step by step") still helps on hard cases.

Best for debugging, algebra, ambiguous problems. Add "explain your reasoning first, then answer" to hard prompts.

See also Few-shot, Self-consistency.

Chat model

Model & training

A fine-tuned model designed for turn-based conversation. Understands system prompts, user turns, and produces assistant responses. What almost everyone uses today. Contrast with a base model.

Chunking

Retrieval

Breaking a long document into smaller pieces so it can be embedded and retrieved. Chunk size and boundaries affect retrieval quality substantially — too small loses context, too large dilutes relevance.

See also Embedding, RAG.

Claude

Model & training

Anthropic's family of large language models. The generations are named for size and speed: Opus (frontier), Sonnet (workhorse), Haiku (fast), Fable (efficient reasoning). Constitutional AI is their alignment technique.

Claude Code, the tool driving this workbook, runs on Claude models. Opus for hard work, Sonnet for daily use.

Constitutional AI

CAISafety & governance

Anthropic's alignment technique: rather than only using human feedback, the model is trained to critique and revise its own outputs against a written set of principles ("a constitution"). Reduces the amount of human labeling needed for safety training.

Context

Context & memory

The full text the model sees when generating — the system prompt, the conversation history so far, any documents you've included, plus your current turn. Everything the model can attend to for this generation.

Context window

Context & memory

The maximum number of tokens the model can attend to in one generation. Ranges from 8K (older models) to 1M+ (Claude Opus, Gemini 1.5 Pro). Determines how much you can put in the prompt.

Larger isn't automatically better — the model may attend less well to content in the middle of a very long context. Break big tasks into focused sessions.

D

Direct Preference Optimization

DPOModel & training

An alternative alignment method to RLHF that skips the separate reward-model step. Simpler pipeline, often comparable results. Increasingly common.

Drift

Capabilities & failures

A failure mode where model output over a long conversation gradually loses accurate context or consistency with earlier turns. The model isn't remembering wrong — it's attending less well to more content.

Symptom: your Claude Code session that was fine for the first hour starts producing worse suggestions in the third hour. Start a fresh session.

E

Embedding

Retrieval

A vector representation of text (or an image, or code) where semantically similar items are close together in vector space. Embeddings enable semantic search: the query and documents both become vectors, and the nearest ones are the most relevant.

See also RAG, Vector store, Semantic search.

Eval

Model & training

Short for evaluation. A test suite for a prompt or an AI-assisted workflow — a set of inputs with expected outputs (or with judgment criteria), run periodically to detect quality drift or compare model versions.

The single highest-leverage engineering practice for AI-heavy work. Build evals for your most repeated Tathkarah workflows.

F

Few-shot prompting

Prompting

Providing two to five worked examples of the input-to-output transformation before asking the model to complete the pattern. Powerful because it activates in-context learning — the model can generalize from a handful of examples remarkably well.

If your zero-shot prompt gives inconsistent output, add three examples. Usually enough.

See also Zero-shot, In-context learning.

Fine-tuning

Model & training

Additional training on a curated dataset, on top of a pretrained model, to specialize behavior. Common flavors: supervised fine-tuning (SFT) on demonstration data, and preference optimization (RLHF, DPO) on ranked pairs.

In 2026, fine-tuning is rarely the answer for a team like ours. Better prompts, better retrieval, and better tool use handle most needs at a fraction of the cost.

Foundation model

Model & training

A very large model, trained on very broad data, adaptable to many downstream tasks. GPT-4, Claude, Gemini, Llama are all foundation models. The term emphasizes the "adapt for anything" property.

Function calling

Tools & agents

A pattern where you describe available functions (with typed parameters) in the prompt, and the model responds with a structured request to call one. Enables the model to trigger real actions in your code.

See also Tool use, Structured output.

G

Grounding

Retrieval

Providing the model with specific factual context so its output is anchored to reality rather than generated from prior alone. Grounding via retrieval (RAG), via tool calls, or via including source documents directly in the prompt.

The most reliable defense against hallucination. If accuracy matters, ground.

H

Hallucination

Capabilities & failures

Model output that is fluent, confident, and factually wrong or fabricated. Not a bug — a consequence of how the model is trained. The model has no distinction between "recall" and "generate"; both produce next-token predictions.

Never trust confidence as a signal of correctness. Always verify.

See also Confabulation, Drift, Grounding.

Hallucination: Confabulation

Capabilities & failures

A specific hallucination shape: plausible narrative that connects real facts incorrectly. "The db.eval() function was removed in MongoDB 5.2" — the function was removed, the version is wrong.

Hallucination: Invention

Capabilities & failures

A specific hallucination shape: the model produces a specific fact — function name, version number, citation — that does not exist. Common with API references and academic citations. Detectable by grep or a documentation lookup.

I

In-context learning

ICLPrompting

The emergent ability of large models to learn a new task from examples given in the prompt, with no weight updates. The mechanism behind few-shot prompting. Somewhat mysterious — still active research.

Inference

Model & training

The process of running a trained model to produce output. Contrast with training, which is the process of creating the model. When you use Claude, you're doing inference; when Anthropic trained Claude, that was training.

Instruction tuning

Model & training

Fine-tuning on a dataset of instructions and their appropriate responses. Turns a base model into one that reliably follows instructions. A foundational step before RLHF.

J

Jailbreak

Safety & governance

A user technique to bypass a model's safety training and get it to produce content it was trained to refuse. Modern models resist most jailbreaks, but the technique is a constant cat-and-mouse.

L

Large Language Model

LLMModel & training

A neural network with billions to trillions of parameters, trained to model human language. All the models an engineer encounters daily — Claude, GPT, Gemini, Llama — are LLMs.

LLM-as-judge

Model & training

Using one LLM to evaluate the outputs of another (or its own outputs). A common eval technique — cheaper than human evaluation, more scalable, but has biases (models often favor their own family's style).

M

Model Context Protocol

MCPTools & agents

An open standard from Anthropic for connecting AI models to external tools and data sources. Lets you plug a database, a filesystem, a Slack integration into Claude without writing custom code per model.

Claude Code uses MCP for its browser tools, iOS simulator, terminal, and more.

Memory (persistent)

Context & memory

Long-term notes an AI system stores about a user, project, or task, that survive across sessions. Claude Code writes memory files at ~/.claude/projects/…/memory/. Distinct from context, which is per-turn.

Model tier

Ops & cost

A capability/speed/cost bracket. Vendors publish multiple tiers: small & fast (Haiku, GPT-4o mini, Gemini Flash), mid (Sonnet, GPT-4o), frontier (Opus, GPT-4 Turbo, Gemini Ultra). Match the tier to the workload.

Model card

Safety & governance

A document published by a model provider describing intended use, known limits, training data, evaluation results, and safety considerations. The public accountability document.

O

Orchestrator

Tools & agents

An agent that coordinates multiple sub-agents to accomplish a larger goal. The orchestrator plans, spawns workers, monitors their results, and composes final output.

Over-refusal

Capabilities & failures

A failure mode where a model refuses reasonable requests because they superficially resemble unsafe ones. Well-aligned models balance helpfulness and safety; over-aligned ones become uselessly cautious.

P

Parameters

Model & training

The learned weights of a neural network. Modern LLMs have tens of billions to trillions. Roughly correlates with capability, but architecture and training data matter as much or more.

Personally Identifiable Information

PIISafety & governance

Data that identifies a natural person — names, emails, phone numbers, government IDs, passport numbers, addresses. Regulated under most data-protection frameworks. Combinations of "safe" fields can re-identify.

The Tathkarah rule: no customer PII ever leaves your machine into an AI tool. No exceptions.

Pretraining

Model & training

The initial, self-supervised training phase on a very large corpus of text. Where the model learns language, world knowledge, code, and some reasoning. Costs tens of millions of dollars and takes weeks to months.

Prompt

Prompting

The text input to the model — instructions, context, question. The single most important thing you control. Good prompt = usable output; bad prompt = wasted call.

Prompt caching

Context & memory

A vendor feature where a long, repeated prefix of your prompt is cached server-side so subsequent calls reuse it without recomputing. Dramatically reduces cost and latency for repeated queries against the same context.

Prompt engineering

Prompting

The discipline of writing, testing, and iterating on prompts to reliably produce useful outputs. An empirical practice — you learn by trying, measuring, adjusting.

Prompt injection

Safety & governance

A security vulnerability where user-supplied content (a customer email, a scraped webpage, a document upload) contains instructions that override the system prompt. The AI-era equivalent of SQL injection.

If you're building any feature that feeds user text into an LLM, design assuming that text can subvert the model. Constrain what the model can do, don't just trust that it will refuse.

R

Rate limit

Ops & cost

A cap set by the vendor on how many requests or tokens you can send per minute/day. Design your integrations to handle rate-limit errors gracefully — back off and retry.

Red team

Safety & governance

A team (or process) that adversarially tests a system to find weaknesses. For AI: trying to jailbreak, extract training data, cause misuse. Standard practice for anyone shipping AI features to customers.

Retrieval-Augmented Generation

RAGRetrieval

A pattern where relevant documents are fetched from a database (via embedding search or classical search) and included in the prompt to ground the model's response. Standard architecture for "chat with my docs" applications.

See also Embedding, Vector store, Grounding.

Reinforcement Learning from Human Feedback

RLHFModel & training

A training method: humans rank model outputs by quality; a reward model learns those preferences; the base model is trained to maximize the reward. The reason modern chat models feel usefully aligned.

Reranking

Retrieval

A second stage after retrieval where a more expensive model re-scores the top-N results for relevance. Improves quality at the cost of extra latency and compute.

S

Sampling

Model & training

The process of picking each output token from the model's probability distribution. Controlled by temperature, top-p, top-k, and other parameters. Determines how random vs deterministic the output is.

Semantic search

Retrieval

Search that matches by meaning rather than by exact keywords. Query and documents are embedded into vectors; nearest-neighbor search returns the most relevant. Better than keyword search for natural-language queries.

Self-consistency

Prompting

A prompting technique where you sample multiple chains of thought for the same problem and take the majority answer. Improves accuracy at the cost of extra tokens.

Structured output

Prompting

Constraining the model to produce output matching a specific schema (usually JSON). Vendors provide this via "JSON mode" or "tool use". Reliable structured output is a hard problem the industry has largely solved by 2025.

Sycophancy

Capabilities & failures

A failure mode where the model agrees with the user's stated position even when it's wrong. Comes from training on human feedback that rewards agreement.

When you want an honest second opinion, phrase your ask neutrally. "Am I right that X?" invites sycophancy; "What's wrong with X?" does not.

System prompt

Context & memory

Instructions from the developer that set persistent behavior for the model across a conversation. Distinct from user turns. Modern models attend strongly to system prompts.

T

Temperature

Model & training

A sampling parameter controlling how "creative" the model is. Zero = always pick the most probable next token = deterministic. Higher values = more variety. For most engineering work, low temperature (0.0 to 0.3) is right.

Token

Model & training

The unit of text the model processes. Roughly 3–4 characters of English or one common word. Arabic and code tokenize more densely (2–3 tokens per Arabic character is not unusual). What you pay for.

Tokenization

Model & training

The process of splitting text into tokens the model can process. Byte-pair encoding (BPE) is the most common algorithm. Different models tokenize the same text differently.

Tool use

Tools & agents

The capability of a model to invoke external functions — search, code execution, database queries, file reads — as part of producing its answer. What turns a chat model into an agent.

Top-p (nucleus sampling)

Model & training

A sampling parameter: consider only the smallest set of tokens whose cumulative probability exceeds p, then sample from that set. Cuts off the long tail of unlikely tokens.

Transformer

Model & training

The neural network architecture underlying all modern LLMs. Introduced by Vaswani et al. in "Attention Is All You Need" (2017). Uses self-attention to process sequences of tokens in parallel rather than sequentially.

V

Vector store

Retrieval

A database optimized for storing and querying high-dimensional vectors (embeddings). Supports fast approximate nearest-neighbor search. Examples: Pinecone, Weaviate, Qdrant, pgvector.

Z

Zero-shot prompting

Prompting

Prompting the model to perform a task with no examples in the prompt, relying entirely on pretrained knowledge and instructions. Simple, cheap, works for common tasks the model has seen countless variations of.

A working dictionary, not a completed one — additions come from the failures we catch and the terms we didn't know we needed.
